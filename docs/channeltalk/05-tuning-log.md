# 05. 튜닝 기록 (v1 → v2)

ALF를 운영하며 실패한 상담을 모으고, 무엇을 고쳐서 결과가 어떻게 바뀌었는지 기록한다.
숫자는 `npm run report -- --from <시작> --to <끝>` 출력에서 옮긴다.

## 측정 방법

| 지표 | 정의 | 출처 |
|---|---|---|
| ALF 해결률 | 상담원이 들어오지 않고 이관되지 않은 상담 / 전체 상담 | `/reports/summary` inquiries |
| 이관율 | 태스크 ESCALATE 또는 상담원 참여 상담 / 전체 상담 | 〃 |
| 이관 사유 분포 | 이관 상담의 사유 코드별 건수 | 〃 escalationReasons |
| 테스트 정답률 | `docs/test-scenarios.md` 30문항 중 기대 결과와 같은 문항 수 | 수동 채점 |

## 결과 요약

| 버전 | 기간 | 상담 수 | ALF 해결률 | 이관율 | 테스트 정답률 | 주요 변경 |
|---|---|---|---|---|---|---|

| v2 | | | | | /30 | |

## 실패 사례

한 건씩 아래 형식으로 남긴다. 고객 원문은 개인정보를 지우고 요약한다.

### F-001 (예시 형식)

| 항목 | 내용 |
|---|---|
| 날짜 / 상담 | 2026-MM-DD / chatId 끝 4자리 |
| 고객 문의(요약) | |
| 기대 | (예: 취소 태스크 실행 → ESCALATE) |
| 실제 | (예: 지식만 보고 "바로 취소됩니다" 답변) |
| 원인 분류 | 지식 누락 / 규칙 모호 / 태스크 트리거 누락 / 태스크 분기 오류 / 허브 정책 / 범위 밖 |
| 수정 | (예: 02-rules 규칙 1 문구 강화, T2 트리거 예시 추가) |
| 확인 | (수정 후 같은 문의 재현 결과) |
